## E3：首轮真实实验与纠错

软件基准为干净提交 `99513f4`，真实模型 `deepseek-v4-pro`、Messages 协议、temperature 0.7。3 个公开任务（阅读、写入、编辑）各重复 2 次，6/6 成功；14 次 API 请求、8 次文件工具调用；API 输入 33465、输出 887、缓存输入 29696 Token。按价格表估算 **0.0667788 元**，用量覆盖率 100%，无未结算预留或预算超限。不是账单金额或总体模型能力证明。独立推理 Token 未由此协议链路单独报告，兼容层的零值不能解释为模型没有推理。

原始控制台出现一次 `aclose(): asynchronous generator is already running` 收尾警告。任务结果不抹除，也不把这一运行宣称为完全无异常。另用参考执行跑两个代码题，Docker 引擎未运行时 Windows 命令返回 1，原评分器误归为 `task_failure`。该结果不应计作模型能力失败。

先新增行为断言，修复前同组为 **0 通过、2 失败、0 跳过，0.48 秒**：最终事件交给 Agent 前底层流必须已关闭；Docker 环境不可用不能启动候选执行或被当成候选错误。修复后同组均通过，加已有评测检查共 **45 通过、0 失败、5.23 秒**。修复将底层流纳入显式关闭，并在容器执行前独立检查镜像/引擎；补充检查探测超时必须杀死并回收进程。

实际 Docker 可用性复验：**0 个可判定代码结果、2 个 `harness_error`**，候选未在宿主执行。修复前误分类保存在 `coding-initial-misclassification.json`，修复后保存在 `coding-corrected.json`，不修改历史证据。该复验使用尚未提交工作树，manifest 如实标记 dirty；提交后的可复现实验将另行保留。
