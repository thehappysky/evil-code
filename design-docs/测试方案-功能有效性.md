# 功能有效性测试方案

> 每项测试只写三件事：做什么、预期效果（什么算正常）、证明了哪个功能有效。

## 1. 权限 fail-closed（P0.1）
- 做什么：让 Agent 循环中模型调用 file_write 写一个文件。
- 预期：文件未被创建；模型收到含 denied 的错误结果。
- 证明：未授权的写操作在真实循环里被拦截，fail-closed 有效。

## 2. 沙箱执行（P0.2 --sandbox）
- 做什么：开启 --sandbox 后执行 shell_exec（机器上未安装 Docker）。
- 预期：返回 "Docker is not installed"，而不是在本机执行命令。
- 证明：shell 工具确实走了沙箱路径，接线有效。

## 3. 技能注入（P0.2 skills）
- 做什么：有可用技能时启动 Agent，检查会话首轮。
- 预期：session 里出现 <available_skills> 及技能列表。
- 证明：技能列表注入有效。

## 4. Token 记账（P2.1）
- 做什么：真实 Agent 跑完一轮，用 headless JSON 模式输出。
- 预期：输出 JSON 的 usage.input_tokens > 0（真实 token 数）。
- 证明：usage 记账真的流到了输出，不是写死 0。

## 5. 工具并行（P5.1）
- 做什么：同一轮调用两个各 sleep 0.2s 的工具。
- 预期：总耗时 < 0.35s（串行需要 0.4s）。
- 证明：工具是并发执行而不是串行。

## 6. Todo 提醒联动（P5.2）
- 做什么：模型先调用 todo_write，再进行下一轮。
- 预期：下一轮 session 出现含待办内容的 <system-reminder>。
- 证明：todo 工具与提醒 hook 联动有效。

## 7. 死循环拦截（P6）
- 做什么：模型连续 4 次调用同一个 shell_exec。
- 预期：第 4 次被拒（denied），命令未执行。
- 证明：DoomLoop 拦截在真实循环里有效。

## 8. 子代理工具（P7）
- 做什么：父 Agent 调用 task 工具触发子代理。
- 预期：父会话出现 <subagent_result> 工具消息。
- 证明：子代理在父循环里端到端可用。

## 9. 弹性重试（P3）
- 做什么：模拟 401 和 5xx 响应。
- 预期：401 后刷新令牌并重试成功；5xx 退避后重试成功。
- 证明：弹性层（重试/刷新）有效。

## 10. 提示词接线
- 做什么：检查 prompts.py 里主提示词与各子提示词。
- 预期：主提示词含身份词，子代理/压缩/计划提示词均非空且被引用。
- 证明：提示词已接线（语义效果不在自动断言范围内）。

## 通过标准

全量 pytest 通过（含新增 8 个有效性用例）。上面任一预期没达到，就说明对应功能坏了。
