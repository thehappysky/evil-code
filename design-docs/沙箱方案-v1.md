# AI Agent 沙箱方案 v1（已实现）

> 2026-08-05 定版。设计目标：用户零配置获得"风险命令自动进沙箱"的安全体验，
> 同时通过项目级隔离、短期环境即删、定时清理与重视度驱逐，保证 Docker 存储不失控。

---

## 1. 核心原则

1. **隔离换免审批**：风险命令不再弹窗询问，而是自动进入 Docker 沙箱执行；
   安全命令保持本机零打扰。
2. **短期即删，长期按重视度驱逐**：临时目录里的环境用完即删；正式项目环境
   在磁盘压力下按"时间窗内访问频率 + 新鲜度"驱逐，受保护项目永不自动删。
3. **绝不静默降级**：Docker 不可用时，风险命令退回显式审批；批准后本机执行
   会明确标记 fallback，headless 下默认拒绝。
4. **只清理自己的资源**：所有容器/卷打 `code-agent.*` 标签，GC 定向清理，
   绝不全局 `docker system prune`（手动 `clean-cache` 除外）。
5. **自动驱逐只删环境，不碰项目源码**。

---

## 2. 路由分类器（sandbox/policy.py）

每条 shell 命令先分类，再决定执行方式：

| 分类 | 档位 | 挂载 | 网络 | 典型命令 |
|:---|:---|:---|:---|:---|
| `local` | — | 本机 | 本机 | ls / cat（安全路径）/ git status / echo |
| `sandbox` | `clean` | 工作区只读 | none | bash script.sh、python -c、cat /etc/shadow、rm -rf |
| `sandbox` | `net` | 工作区只读 | 白名单代理 | curl、wget |
| `sandbox` | `work` | 工作区只读 + /env 卷可写 | 白名单代理 | pip install、npm install、python test.py（工作区内） |

规则优先级（从高到低）：

1. `SCRIPT_EXECUTORS`（bash/sh/python/node/pwsh/cmd/xargs/eval...）一律进沙箱，
   永不本机执行；shell 类 → clean，解释器类按脚本位置分 clean/work。
2. 包安装器（pip/npm/poetry/uv/cargo/apt...）→ work。
3. 联网工具（curl/wget）→ net；git 写子命令（clone/pull/push...）→ work。
4. 白名单命令若参数命中敏感路径（/etc/shadow、~/.ssh、.env、*.pem...）→ clean。
5. 白名单命令且参数安全 → local。
6. 其余未分类 → clean（fail-safe）。

生命周期：项目根位于系统临时/缓存目录 → `ephemeral`（用完即删）；
否则 → `persistent`（磁盘压力下驱逐）。

## 3. 容器与卷（sandbox/manager.py）

- **每项目一个 work 卷**：`code-agent-<project_id>-work`，显式创建并带标签
  （`code-agent.managed` / `code-agent.project` / `code-agent.lifecycle`）。
  卷挂在容器 `/env`，`PIP_CACHE_DIR`、`PYTHONUSERBASE`、`npm_config_*`、`PATH`
  都指向 /env，依赖跨命令保留。
- **容器全部临时**：每条命令 `docker run --rm`，clean/net 无状态；
  work 容器状态在卷里。容器不是长期资源，不需要休眠/TTL。
  net 档有会话级复用容器（`docker exec`），工作目录变化或启用自定义 profile
  时自动回退到每次 `docker run`。
- 所有档位以容器内 root 运行（隔离仍成立），避免 uid 1000 无 passwd 条目
  导致 whoami 等命令报错，同时保证 pip/npm/apt 可写系统路径。
- 工作区统一只读挂载；代码修改走宿主侧 file_edit/file_write/file_delete 审批，容器不写源码。
  > **注**：删除文件必须用 `file_delete` 工具（宿主侧 + 审批），**不可**用 `shell_exec rm`。
  > `rm` 被分类器归入 `clean` 档（fail-safe），而 clean 档工作区只读，`rm` 会静默失败。
  > `file_delete` 不在任何权限预放行集合中，自动走 ASK/DENY（与 file_write 同路径）。
- 精细化挂载：所有档位提供 `/scratch` tmpfs（`TMPDIR=/scratch`），
  临时文件/缓存不落工作区；work 档另有持久 `/env` 卷。

## 3.1 自定义 profile（sandbox.toml）

```toml
[sandbox]
profile = "ci"          # 或 --sandbox-profile / CODE_AGENT_SANDBOX_PROFILE

[sandbox.profiles.ci]
extends = "workspace"
read_only = ["D:/shared-readonly"]   # → 容器 /mnt/ro-0, /mnt/ro-1...
read_write = ["D:/shared-rw"]        # → 容器 /mnt/rw-0, /mnt/rw-1...
deny = [".env", "secrets"]           # 工作区内路径 → 空占位绑定（不可读）
restrict_network = true              # true → 所有档位强制无网络
```

- 全局 `~/.code-agent/sandbox.toml` 与项目 `.code-agent/sandbox.toml` 合并；
  全局已定义的 profile 名项目不可覆盖（仿 grok 语义）。
- deny 只支持工作区内相对路径（绝对路径若在工作区内也会转换）；
  工作区外路径不挂载，容器天然不可见。
- 启用自定义 profile 时 net 档关闭容器复用（挂载策略随项目变化）。

## 4. 出站白名单（sandbox/proxy.py）

- net/work 容器注入 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`，指向宿主机过滤代理。
- 代理监听 `0.0.0.0`，容器经 `host.docker.internal` 访问；
  `proxy_url` 固定返回 `http://host.docker.internal:<port>`（容器可达地址）。
- 默认白名单：pypi.org、files.pythonhosted.org、github.com、npmjs.org、
  nodejs.org、example.com 等；后续通过 sandbox 配置扩展。
- 支持 CONNECT 隧道与 absolute-URI HTTP 转发；非白名单域名一律 403。
- 诚实边界：只约束走代理的工具；裸 socket 直连拦不住（clean 档 `--network none`
  无此问题）。`egress=open` 是显式降级，不是默认。

## 5. 权限联动（permission/manager.py + TUI adapters）

- `PermissionManager` 增加 `sandbox_mode` + `sandbox_available`：
  - 分类为 sandbox 且 Docker 可用 → `ALLOW`（reason: `sandbox_auto:<tier>:<原因>`）；
  - 分类为 sandbox 且 Docker 不可用 → 交互模式 `ASK`（弹窗带原因链），
    headless 默认 `DENY`；
  - 安全命令 → 仍 `ALLOW`（local）。
- TUI 审批弹窗与工具卡片显示 `last_reason`（沙箱档位/风险原因）。
- TUI、REPL、headless 共用同一决策路径。
- 子代理（subagent）也接入同一沙箱管理器，且 `allow_fallback=False`：
  Docker 不可用时子代理内风险命令直接失败，绝不静默回退本机。

## 6. 生命周期与清理

触发点：

1. 新建项目环境前：项目数超过 `max_projects`（默认 10）→ 驱逐低重视度项目卷；
2. 运行期定时 GC（TUI 每 10 分钟）：清理已退出受管容器、悬空 ephemeral 卷、
   超限项目、磁盘水位超限时的低重视度卷；
3. 手动命令：`code-agent sandbox gc / clean-cache / list / protect / remove`。

重视度 = 最近 7 天窗口内访问次数（窗口过期清零），平手看新鲜度；
`/sandbox protect` 等价 `code-agent sandbox protect <id>` 标记保护。

磁盘水位通过 `docker system df` 统计镜像/容器/卷/缓存总占用，
超警戒线（默认 10GB）驱逐低重视度 persistent 卷。

## 7. 使用方式

- 默认 `auto`：无需任何参数，风险命令自动进沙箱。
- `--sandbox`：全部 shell 命令强制沙箱（strict）。
- `CODE_AGENT_SANDBOX=off|auto|strict` 环境变量覆盖。
- TUI 状态栏显示 `sandbox:auto` 等；工具卡片显示实际档位。
- 管理命令：`code-agent sandbox list|gc|protect|remove|clean-cache|status`。
- TUI 内：`/sandbox status|list|gc|clean-cache|protect|unprotect|remove <id>`。
- 配置文件 `~/.code-agent/sandbox.toml`（全局）与 `<workspace>/.code-agent/sandbox.toml`
  （项目，追加式）：可配 `image`（国内网络可指向镜像加速源）、`egress_extra`
  （白名单追加域名）、`max_projects`、`disk_warning_gb`、`profile` + `profiles.*`。
- Draft 工作副本（git worktree）：
  - `code-agent draft create [PROJECT_ROOT]` 或 TUI `/draft create`；
  - `draft list|status <id>|merge <id>|discard <id>`；
  - 副本在 `~/.code-agent/drafts/<project_id>/<draft_id>`，独立分支与独立沙箱卷；
  - merge 要求主工作区干净，冲突自动中止并保留副本；discard 删除 worktree/分支/卷。

## 8.1 真机冒烟结果（2026-08-06，Docker Desktop 28.5.2）

- Docker 引擎可用、`code-agent sandbox gc/list` 正常（含磁盘水位统计）。
- clean 档：容器内 `root`、`/workspace` 只读（touch 报 Read-only file system）。
- work 档：`pip install --user six` 经白名单代理成功；下一条命令
  `python -m pip show six` 在**同一个 work 卷**找到包（跨命令状态保留）。
- 出站拦截：`pip install --index-url http://blocked-egress-test.invalid/...`
  被代理拒绝（日志 `Egress denied ...`），命令失败。
- 自定义 profile：`deny = [".env","secrets"]` 生效（.env 长度 0、secrets 空目录）；
  read_only/read_write 挂载到 /mnt/ro-0、/mnt/rw-0；/scratch tmpfs 就位。
- net 复用容器：docker exec 执行成功，工作区与 /scratch 可见。
- 环境要求：Docker Hub 直连不通时（国内网络），在 sandbox.toml 配置
  `image = "docker.1ms.run/library/python:3.12-slim"` 等可达加速源。

## 9. 已知边界与 v2 清单

- 沙箱是 Linux 容器：Windows 原生命令（cmd/dir/type）在沙箱内不可用，会明确失败。
- **工作区只读 vs. 删除操作**：`rm`/`mv`/`cp`/`sed -i` 等针对工作区的写/删命令被分类器
  归入 `clean` 档（fail-safe），但 clean 档工作区只读挂载，这些命令会**静默失败**。
  已通过 `file_delete` 工具解决"删除"场景（宿主侧 + 审批）；其余写操作（mv/cp 等）
  仍应走 file_edit/file_write，未提供专门工具的暂未覆盖。
- work 卷状态不跨档继承；需要"安装后使用"的流程在 work 档内完成。
- 出站白名单依赖工具走代理；更强制措施（每容器网络隔离）留 v2。
- 已落地（原 v2 项）：TUI `/sandbox` 命令、sandbox.toml 配置、真实卷大小驱逐。
- 已落地：Draft 工作副本（git worktree）、自定义 profile（extends/deny/
  restrict_network）、net 容器复用、精细化挂载（/scratch + profile 挂载）。
- 后续可选：容器级 seccomp/更强制网络隔离、按卷真实大小的更细调度。
