# Evil Code 大模型 / Agent 评测建设方案

日期：2026-10-26。评测对象是指定模型与 Evil Code 推理循环、工具、工作区约束共同组成的系统；软件回归测试与真实模型任务评测分别报告。

每批记录通过、失败、跳过、覆盖率和耗时。不降门禁、不删除用例。小样本和单次耗时不用于宣称模型优劣或性能提升。阶段完成即提交并推送同一功能分支，未经要求不合并主分支。

## 数据设计

核心公开任务集覆盖文件理解、结构化输出、文件编辑、跨文件操作、只读约束、指令注入防御和异常恢复；正向任务与拒绝/不操作任务共同存在。任务包含 ID、版本、类别、难度、指令、初始文件、允许写入范围、判题规则和参考执行。

代码修复任务另用 Docker 内运行的独立测试判定；生成代码不在宿主机执行。初始参考程序和参考执行只供确定性判题自检，不给真实模型，不作为模型能力分数。公开题集是开发集，不能当作未见过的隐藏基准；后续生产验收集应独立保管、去重和人工审核。

每次尝试创建空白临时工作区，不复用历史、用户记忆或个人凭证文件。模型只接收任务指令、初始文件内容经工具读取的结果，以及原有系统提示；不能读取评分器或参考答案。任务必须明确验收要求，允许多种合理实现，不强制唯一工具顺序。

## 指标口径

| 指标 | 口径 |
| --- | --- |
| 端到端完成率 | 成功尝试 / 已计划尝试；预算未启动、超时及服务错误分别分类 |
| 能力完成率 | 成功 / 可判定的成功与任务失败；明确单独列出被排除的基础设施问题 |
| 分类别完成率 | 按类别、难度和 task ID 展示，不只展示总分 |
| pass@1 / pass@k | 按任务重复采样；k 大于有效采样数时不输出分数；采用组合数无偏估计 |
| 重复稳定性 | 所有计划重复均成功的任务比例，不把缺失尝试当作成功 |
| 不确定性 | 按任务聚类 bootstrap 的 95% 区间；任务不足时返回未知，小样本明确标注 |
| 工具质量 | 请求数、错误、拒绝、无效参数；不要求固定调用顺序 |
| 安全与遵循 | 禁止路径访问尝试、实际越界写入、约束违反；与正常安全拒绝分别统计 |
| 时延 | 首个可见文本时间、完整尝试的 P50/P95；成功与所有尝试分别保留 |
| Token | API 报告的输入、输出、缓存、推理 Token；缺失为未知，不能写成零 |
| 费用 | 根据显式价格表计算的估算费用；所有失败请求也计入预算；不是账单证明 |
| 成功任务成本 | 全部尝试成本 / 成功尝试数；零成功或费用不全时返回未知 |
| 人工评审 | 事实、完整性、修改质量与证据的一致性；规则、标注分歧和评分器版本留痕 |

任务判题以最终文件/结构化结果/独立测试为主。工具路径检查记录可见行为。模型裁判不替代可执行正确性测试；本轮优先交付确定性评分及人工复核模板，自动模型裁判的校准另立后续批次。

## 实验与预算

用户授权：使用本机已配置模型，真实评测预算不超过人民币 5 元。当前检测到官方 DeepSeek 接口、`deepseek-v4-pro`、Messages 协议；不把密钥写入命令行、日志或版本库。

使用核对当日的官方高峰价作为保守费率：每百万输入（未命中）9 元、缓存输入 0.30 元、输出 27 元。来源：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/ 。实际空闲价可能更低。每次请求前预留输入/输出上界费用，遇用量缺失、错误或中断保留预留额，不自动重试。预算不足不启动新请求；额外设置请求次数、输出 Token、轮数及超时上限。估算预算不是服务商账户硬限额，真实用量口径不完整时保守停止并报告。

首轮真实实验从少量公开任务与重复开始，目标是跑通真实链路、暴露问题，不对小样本结果作总体排名。固定数据集哈希、软件提交、提示词哈希、工具列表、模型/协议、采样参数、资源上限和价格版本。对比只接受相同任务集合与实验口径，拒绝将离线参考执行与真实模型作能力排名。

## 产物与隐私

本地原始运行写入被 Git 忽略的 `.eval-runs/`，包含 manifest、逐次 JSON、可见轨迹、评分细节、JSON/CSV/Markdown/HTML 汇总和人工复核模板。不保存隐藏思维链。仅显式导出的脱敏汇总进入 `progress/evidence/日期/` 并上传公开仓库。

## 已知边界与后续

本机 Docker Desktop 未运行，因此本轮不能把容器代码修复评测计为已验证；容器判题器需保留不可用记录。工作区路径钩子是工具层限制，不是完整 OS 沙箱。真实客户端禁用 shell、网络工具、插件、MCP 和子代理，以减少首版评测的环境噪声；此结果只代表明确受限配置，不代表完整产品所有能力。

后续：扩大任务和真实用户反馈集；独立保密验收集；真实容器验证；多模型/多版本配对实验；经人工校准的模型裁判；更严格的 OS 隔离；线上效果与回归联动。

参考方法：Anthropic Agent eval 实践 https://www.anthropic.com/research/demystifying-evals-for-ai-agents ；HumanEval pass@k 实现 https://github.com/openai/human-eval/blob/master/human_eval/evaluation.py 。
